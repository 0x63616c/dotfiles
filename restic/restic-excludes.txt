# restic --exclude-file for the macbook-pro repo.
#
# Rule of thumb: exclude only what a package manager, compiler, or app can
# rebuild from scratch. Everything else stays in, because the failure mode of a
# curated allow-list is that you discover the missing thing at restore time.
#
# Sizes are from `du -sh -x` on 2026-07-28 and are here to justify each line —
# they will drift, that's fine.
#
# Absolute paths, not $HOME — restic's env expansion in exclude files is not
# worth relying on when a silent miss means backing up 30G of caches.

# ── Network storage that -x CANNOT catch ──────────────────────────────────────
# This one bit us on the first run: restic reported 9.06 TB to process instead
# of ~128 GB, because CloudMounter-Homelab maps the NAS's own Homelab share and
# restic walked straight into it — reading the NAS over the network in order to
# back it up onto the NAS.
#
# --one-file-system (-x) does not help here. macOS File Provider mounts under
# ~/Library/CloudStorage (CloudMounter, OneDrive, Dropbox, Google Drive) are NOT
# real mounts: they never appear in `mount`, and they report the SAME st_dev as
# the home directory (16777230 for all of /Users/calum, .../CloudStorage, and
# .../CloudMounter-Homelab). There is no filesystem boundary for -x to stop at,
# so this has to be an explicit path exclude.
#
# -x still earns its place for genuine mounts: /Volumes/* SMB shares and the
# OrbStack NFS mount. It is simply blind to exactly the directory modern macOS
# uses for network storage.
#
# Note ~/Library/Mobile Documents (iCloud Drive) is deliberately NOT excluded —
# it is fully materialised locally (zero .icloud stubs) and is real data.
/Users/calum/Library/CloudStorage

# ── Scratch ───────────────────────────────────────────────────────────────────
/Users/calum/yt-tmp                         # 5.8G

# ── Photos library ────────────────────────────────────────────────────────────
# 31G, of which originals/ is 57M. iCloud Photos with "Optimise Mac Storage" is
# on, so the full-resolution photographs are NOT on this Mac — this directory is
# a database plus thumbnails. Backing it up would store 31G and recover no
# photographs.

# The actual photos have exactly one copy and it is Apple's. Fixing that needs
# Immich / osxphotos pulling originals down; see the follow-ups in the README.
/Users/calum/Pictures/Photos Library.photoslibrary

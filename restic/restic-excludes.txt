# restic --exclude-file for the macbook-pro repo.
#
# Rule of thumb: exclude only what a package manager, compiler, or app can
# rebuild from scratch. Everything else stays in, because the failure mode of a
# curated allow-list is that you discover the missing thing at restore time.
#
# ─────────────────────────────────────────────────────────────────────────────
# FORMAT WARNING, learned the hard way:
#
# restic only treats a line as a comment when '#' is the FIRST character.
# There is no inline-comment support. An earlier version of this file wrote
#
#     /Users/calum/Library/Caches                 # 30G
#
# which restic read as the literal pattern "/Users/calum/Library/Caches
# <spaces> # 30G". It matched nothing, silently. Every annotated line here was
# dead, and the first real snapshot came out 239 GiB instead of ~145 GiB with
# ~94 GiB of caches in it. Nothing warns you — the run just succeeds.
#
# So: sizes go in a comment ABOVE the path, never after it. Never put anything
# on a path line.
# ─────────────────────────────────────────────────────────────────────────────
#
# Absolute paths, not $HOME — restic's env expansion in exclude files is not
# worth relying on when a silent miss means backing up 30G of caches.
#
# Sizes measured 2026-07-28 with `du -sh -x`; they drift, that's fine. Note du
# reports ALLOCATED blocks, so it is blind to sparse files — see the VM disk
# section below for why that matters.

# ── Network storage that -x CANNOT catch ──────────────────────────────────────
# CloudMounter-Homelab maps the NAS's own Homelab share, so restic walked into
# it and began reading the NAS over the network in order to back it up onto the
# NAS.
#
# --one-file-system (-x) does not help. macOS File Provider mounts under
# ~/Library/CloudStorage (CloudMounter, OneDrive, Dropbox, Google Drive) are NOT
# real mounts: they never appear in `mount`, and report the SAME st_dev as the
# home directory (16777230 for all of /Users/calum, .../CloudStorage and
# .../CloudMounter-Homelab). No boundary exists for -x to stop at.
#
# -x still earns its place for genuine mounts: /Volumes/* SMB shares and the
# OrbStack NFS mount. It is simply blind to the one directory modern macOS uses
# for network storage.
#
# ~/Library/Mobile Documents (iCloud Drive) is deliberately NOT excluded — it is
# fully materialised locally (zero dataless files) and is real data. It is slow
# to read (File Provider IPC per file), which --read-concurrency compensates for.
/Users/calum/Library/CloudStorage
